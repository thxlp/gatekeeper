ตรวจรอบล่าสุด **2026-08-08** (รอบแรก 2026-08-07 ไม่ได้จดรายการไว้จึงตรวจใหม่ทั้งหมด)
ไฟล์นี้คือรายการงานที่ส่งต่อกันได้ — เจอปัญหาใหม่ให้เพิ่มท้ายหมวด อย่าเก็บไว้ในหัว

## 1. บั๊กที่ผู้ใช้เจอจริง

### ✅ 1.1 มือถือออกจากระบบไม่ได้เลย
`/account` ถูกลิงก์จาก `IconRail` ที่เดียว ซึ่งเป็น `hidden … sm:block` (เดสก์ท็อปเท่านั้น)
และปุ่ม "ออกจากระบบ" อยู่ในหน้านั้นหน้าเดียว → ผู้ใช้มือถือเข้าหน้าบัญชีไม่ได้ ออกจากระบบไม่ได้
**แก้:** เพิ่มปุ่มบัญชี (+ ไฟล์เริ่มงาน) ใน `TopBar` แบบ `sm:hidden` โผล่ทุกหน้าเหมือน rail

### ✅ 1.2 รายการ runtime ไม่ตรงกันสองที่
`/deploy` ให้เลือก node/static/python/docker แต่ฟอร์มแก้ไขบนแดชบอร์ดมีแค่ node/static
พร้อมคอมเมนต์เก่าว่า "python/docker ยังไม่รองรับ" ซึ่งไม่จริงแล้ว → เปิดแก้ไขแอป python
แล้ว `<select>` ไม่มี option ที่ตรงกับค่าปัจจุบัน เผลอบันทึกทับเป็น node ได้
**แก้:** ย้ายไปไว้ที่ `lib/runtimes.ts` ที่เดียว

### ✅ 1.3 กด Enter ในฟอร์ม login/register/forgot-password ไม่ทำอะไร
ทั้งสามหน้าไม่มี `<form>` เลย เป็น `<div>` + ปุ่ม `onClick` → ต้องเอื้อมไปกดปุ่มอย่างเดียว
และเบราว์เซอร์ไม่รู้ว่านี่คือฟอร์ม login จึงไม่เสนอบันทึกรหัสผ่าน
**แก้:** `<AuthForm>` ครอบ + ปุ่มเป็น `type="submit"` + ใส่ `autoComplete` ให้ทุกช่อง

### ✅ 1.4 อัปโหลด zip เกิน 50MB รู้ตัวตอนอัปโหลดเสร็จ
backend จำกัด 50MB (`MAX_ARCHIVE_UPLOAD_BYTES`) แต่ frontend ไม่เช็คขนาดก่อนส่ง
ผู้ใช้เน็ตช้ารอเป็นนาทีแล้วได้ 413 เปล่าๆ
**แก้:** เช็ค `size` ตั้งแต่ตอนเลือกไฟล์ + ข้อความบอกให้ลบ `node_modules` ก่อนบีบอัด

### ✅ 1.5 error ถูกกลืนเงียบ 3 จุด
`.catch(() => undefined)` ทำให้หน้าโหลดค้าง/ว่างโดยไม่บอกเหตุผล:
- `settings` โหลดข้อมูลบัญชีไม่ได้ → การ์ดค้าง skeleton ตลอดกาล
- `databases` โหลดรายชื่อแอปไม่ได้ → ตัวเลือก "ผูกกับแอป" ว่างเปล่า
- `deploy?appId=` โหลดรายละเอียดไม่ได้ → ไม่รู้ว่ากำลัง redeploy แอปไหน

**แก้:** ทั้งสามจุดเด้ง toast บอกเหตุผล
(ที่จงใจให้เงียบและ **ห้ามแก้**: logout, กระดิ่งแจ้งเตือน — พังแล้วต้องไม่รบกวนงานหลัก)

## 2. การเข้าถึง (accessibility)

### ✅ 2.1 StarterFilesModal ไม่มี focus trap
ดัก Escape อย่างเดียว → Tab หลุดไปโฟกัสของหลังกล่องที่กดไม่ได้ และปิดแล้วโฟกัสหายไปที่ body
**แก้:** แยก `lib/use-modal-a11y.ts` ออกมาจาก `ConfirmDialog` แล้วใช้ร่วมกันทั้งสองกล่อง
(กล่อง modal ใหม่ทุกกล่องต่อจากนี้ให้เรียก hook นี้)

### ✅ 2.2 ช่องกรอกหน้า auth ไม่มี label ผูกกับ input
label เป็น `<div>` ลอยๆ → screen reader อ่านไม่รู้ว่าคู่กัน และคลิกข้อความไม่โฟกัสช่อง
**แก้:** `<label htmlFor>` + `id` + `aria-invalid`/`aria-describedby` ตอนมี error

### ✅ 2.3 input อีก ~20 จุดยังไม่ผูก label
ส่วนใหญ่อยู่ใน `/deploy` (`InputRow`, `SelectRow`, ช่อง env var) และฟอร์มแก้ไขบนแดชบอร์ด
**แก้:** ช่องที่มี label มองเห็นอยู่แล้ว → `<label htmlFor>` + `id` จาก `useId()`
(`InputRow`/`SelectRow` ใน /deploy, `PasswordField` ใน /account, `EditRow` บนแดชบอร์ด —
สามตัวนี้เป็นทางเดียวที่ฟอร์มเหล่านั้นสร้างช่องกรอก แก้ที่นี่ครอบคลุมเกือบหมด)
ช่องที่ไม่มี label มองเห็น (ค้นหา, env var ในตาราง, token, โดเมน, ชื่อ DB, รหัส 2FA) → `aria-label`
ตรวจซ้ำแล้วเหลือแต่ `<select>` tail ใน LogsTab ที่อยู่ใน `<label>` ครอบอยู่แล้ว (ถูกอยู่)
แถมที่เจอตอนแก้: ช่อง token (settings) กับรหัส 2FA กด Enter ส่งฟอร์มไม่ได้ → ใส่ให้แล้ว
และรหัส 2FA ได้ `inputMode="numeric"` + `autoComplete="one-time-code"` (มือถือขึ้นแป้นเลข)

### ⬜ 2.4 ยังไม่เคยตรวจด้วยคีย์บอร์ดล้วน/screen reader จริง
รายการข้างบนมาจากการอ่านโค้ด ควรลองไล่ทั้งแอปด้วย Tab อย่างเดียวสักรอบ

## 3. ใช้งานได้แต่ไม่ดี

### ✅ 3.1 หน้าบันทึกการใช้งาน (`/audit`) ไม่มีตัวกรอง/ค้นหา/แบ่งหน้า
เดิม `GET /audit` คืน**ทุกแถวที่เคยเกิดขึ้น**แล้ว frontend render หมด — log โตขึ้นเรื่อยๆ
หน้าจะอืดและหาอะไรไม่เจอ
**แก้:** ย้ายการกรองไปฝั่ง backend (`queryByAccount` — decision/ค้นหา/offset/limit,
เรียงใหม่สุดก่อน, cap 500) + หน้าเว็บมีช่องค้นหา (หน่วง 300ms), ชิปกรองตามผลตัดสิน,
ปุ่ม "โหลดเพิ่ม" ทีละ 100 แถว และตัวนับ "แสดง X จาก Y"
*หมายเหตุ: audit.log ยังเป็นไฟล์แบน append-only ต้องอ่านทั้งไฟล์อยู่ดี — ถ้าวันหนึ่งอ่านช้า
ค่อยย้ายไป Postgres แล้ว query จริง ตอนนี้อย่างน้อย response ไม่โตตามอายุระบบแล้ว*

### ✅ 3.1a บรรทัดเสียบรรทัดเดียวทำให้ log หายทั้งไฟล์
เจอตอนไล่ตรวจ `/audit` ซ้ำ (2026-08-08): `readAll()` ครอบ try/catch รอบ `.map(JSON.parse)`
ทั้งก้อน → มีบรรทัดใดเสีย (เขียนไม่จบเพราะดิสก์เต็ม/ไฟดับกลาง append) จะ `return []` ทั้งไฟล์
หน้า `/audit` ขึ้น "ยังไม่มีเหตุการณ์" ทั้งที่มี 782 แถว = **ล้มไปทางที่บอกความจริงผิด**
**แก้:** try/catch ต่อบรรทัด ข้ามตัวที่เสีย + นับแล้ว `logger.warn` (ไม่กลืนเงียบ — audit log
ที่มีรอยขาดคือสัญญาณที่คนดูแลต้องรู้) · ยืนยันแล้วกับ log จริง: ยัดบรรทัดเสีย 2 บรรทัด
ลอจิกเดิมได้ 0 แถว ลอจิกใหม่ได้ 782 แถวครบ

### ✅ 3.1b ช่องค้นหาไม่ครอบสิ่งที่เห็นบนแถว
คอลัมน์รายละเอียดโชว์ `score=N` และ `N findings` (จาก `auditDetail()`) แต่ backend ค้นแค่
`stage/decision/reason/requestId` → พิมพ์เลขที่มองเห็นอยู่บนจอแล้วหาไม่เจอ
**แก้:** แยกเป็น `haystack()` ครอบ ts + stage + decision + reason + requestId + score
(ทั้ง `8` และ `score=8`) + `N findings` · ระวังไว้แล้วว่า `score` เป็น 0 ได้ ห้ามใช้
`filter(Boolean)` กรอง ไม่งั้น score=0 หลุด (ใน log จริงมี score=0 อยู่ 9 แถว)

### ✅ 3.1c ไม่มีตัวกรองช่วงวันที่
เดิมกรองได้แค่ผลตัดสิน + คำค้น ไล่หา "เกิดอะไรขึ้นวันนั้น" ไม่ได้ (ค้น `2026-07` พอได้เพราะ
ts เป็น ISO แต่ตารางแสดงเวลาแบบ localized ผู้ใช้ค้นด้วยรูปแบบที่ตาเห็นแล้วไม่เจอ)
**แก้:** `from`/`to` ที่ `GET /audit` + `<input type="date">` สองช่องบนแถบตัวกรอง

⚠️ **กับดักที่ต้องระวังถ้าจะแก้ตรงนี้อีก — timezone:** เซิร์ฟเวอร์รัน UTC และ ts ใน log เป็น UTC
แต่ผู้ใช้เลือก "วัน" ตามปฏิทินที่ตัวเองเห็น (ไทย = UTC+7) ถ้าส่งแค่ `2026-07-18` ไปให้เซิร์ฟเวอร์
เดาขอบวันเอง ผลจะเคลื่อน 7 ชม. — ดีพลอยตอน 18 ก.ค. 01:24 น. ตามเวลาไทย ถูกเก็บเป็น
`2026-07-17T18:24Z` เลือกวันที่ 18 จะหาไม่เจอ (ใน log จริงมีแถวแบบนี้ 23 แถว)
จึงให้ **frontend คำนวณขอบวันเป็น ISO instant ตาม timezone ของเครื่องผู้ใช้** แล้วส่งไป
(`toDayStart`/`toDayEnd` ในหน้า `/audit`) เซิร์ฟเวอร์แค่เทียบเวลา ไม่เดาอะไรเลย
ปลายช่วงต้องเป็น 23:59:59.999 ไม่ใช่ 00:00 ของวันนั้น ไม่งั้นแถวของวันที่เลือกหายเกือบหมด

`max`/`min` ของสองช่องผูกกันไว้ ให้เบราว์เซอร์กันเลือกช่วงกลับหลังตั้งแต่ต้น ไม่ใช่ปล่อยให้ผล
ออกมา 0 แถวแล้วผู้ใช้มางงว่าทำไม

**ยังไม่ทำ (ตัดสินใจกันก่อน):** audit.log ไม่มี rotation/retention เลย + ทุก request
อ่านทั้งไฟล์ (ตอนนี้ 180KB/782 แถว ยังไม่รู้สึก) — จะย้าย Postgres หรือ rotate+archive
ต้องคุยกันก่อน (เป็น audit log การลบทิ้งลดคุณค่าเชิงนิติวิทยา archive ดีกว่า trim)

### ✅ 3.2 ไม่มีปุ่ม "ลองใหม่" ตอนโหลดพัง
หลายหน้าโชว์ข้อความ error แล้วจบ ต้องรีเฟรชทั้งหน้าเอง (ซึ่งทิ้งคำค้น/ตัวกรอง/ฟอร์มที่พิมพ์ค้างไว้)
**แก้:** `ErrorBanner` ใน `components/ui/states.tsx` — มีปุ่มลองใหม่ในตัว ใช้ที่แดชบอร์ด, /audit,
/databases, การ์ด Usage, DomainsTab, VariablesTab, LogsTab, /apps/[id]

ระหว่างแก้เจอว่าหลายหน้าเอา error ของ **การโหลด** กับ error ของ **การกดปุ่ม** มาใส่ state
ตัวเดียวกัน ปุ่ม "ลองใหม่" จึงกำกวม (ลบไม่สำเร็จ แล้วกดลองใหม่ = ไปโหลดรายการ?) จึงแยกเป็น
`loadError` (มีปุ่มลองใหม่) กับ error ของ action ที่ไปเด้ง toast — **กติกาต่อจากนี้:**
error ของการโหลด → `ErrorBanner` + onRetry · error ของการกดปุ่ม → `toast.error`

### ✅ 3.3 หน้าว่าง (empty state) ยังเป็นข้อความเปล่าๆ
**แก้:** `EmptyState` ใน `components/ui/states.tsx` (ไอคอน + หัวข้อ + คำอธิบาย + ปุ่มขั้นถัดไป)
ใช้ที่ /databases, DomainsTab, VariablesTab, /audit (ทั้งเคสว่างจริงและเคสกรองไม่เจอ)
และย้ายหน้าว่างของแดชบอร์ดที่ทำไว้แล้วมาใช้ตัวเดียวกัน
ปุ่มที่ฟอร์มอยู่ในหน้าเดียวกัน (DB/โดเมน/ตัวแปร) โฟกัสไปที่ช่องกรอกให้เลย ไม่ใช่แค่บอกว่า
"เพิ่มด้านล่าง" · หน้าว่างเล็กๆ ที่ไม่มีขั้นถัดไปให้ทำ (กระดิ่งแจ้งเตือน, log ว่าง, findings)
ปล่อยเป็นข้อความตามเดิม

## 4. เช็คแล้วไม่มีปัญหา (ไม่ต้องทำ)

- `alert()` / `confirm()` ของเบราว์เซอร์ถูกแทนด้วย Toast/ConfirmDialog หมดแล้ว
- `setInterval` ทุกจุดมี cleanup ครบ ไม่มี timer รั่ว
- แถบล่างมือถือไม่บังเนื้อหา (layout กัน `pb-[60px] sm:pb-0` ไว้แล้ว)
- ตาราง `/audit` มีเวอร์ชันการ์ดสำหรับมือถือแยกอยู่แล้ว ไม่ล้นจอ
- ปุ่ม submit ทุกหน้ามี `disabled` ตอนกำลังส่ง
