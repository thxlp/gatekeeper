## 1. บั๊กที่ผู้ใช้เจอจริง

### ✅ 1.1 มือถือออกจากระบบไม่ได้เลย
`/account` ถูกลิงก์จาก `IconRail` ที่เดียว ซึ่งเป็น `hidden … sm:block` (เดสก์ท็อปเท่านั้น)
และปุ่ม "ออกจากระบบ" อยู่ในหน้านั้นหน้าเดียว → ผู้ใช้มือถือเข้าหน้าบัญชีไม่ได้ ออกจากระบบไม่ได้
**แก้:** เพิ่มปุ่มบัญชี (+ ไฟล์เริ่มงาน) ใน `TopBar` แบบ `sm:hidden` โผล่ทุกหน้าเหมือน rail

### ✅ 1.2 รายการ runtime ไม่ตรงกันสองที่
`/deploy` ให้เลือก node/static/python/docker แต่ฟอร์มแก้ไขบนแดชบอร์ดมีแค่ node/static
พร้อมคอมเมนต์เก่าว่า "python/docker ยังไม่รองรับ" ซึ่งไม่จริงแล้ว → เปิดแก้ไขแอป python
แล้ว `<select>` ไม่มี option ที่ตรงกับค่าปัจจุบัน เผลอบันทึกทับเป็น node ได้
**แก้:** ย้ายไปไว้ที่ `lib/runtimes.ts` ที่เดียว

### ✅ 1.3 กด Enter ในฟอร์ม login/register/forgot-password ไม่ทำอะไร
ทั้งสามหน้าไม่มี `<form>` เลย เป็น `<div>` + ปุ่ม `onClick` → ต้องเอื้อมไปกดปุ่มอย่างเดียว
และเบราว์เซอร์ไม่รู้ว่านี่คือฟอร์ม login จึงไม่เสนอบันทึกรหัสผ่าน
**แก้:** `<AuthForm>` ครอบ + ปุ่มเป็น `type="submit"` + ใส่ `autoComplete` ให้ทุกช่อง

### ✅ 1.4 อัปโหลด zip เกิน 50MB รู้ตัวตอนอัปโหลดเสร็จ
backend จำกัด 50MB (`MAX_ARCHIVE_UPLOAD_BYTES`) แต่ frontend ไม่เช็คขนาดก่อนส่ง
ผู้ใช้เน็ตช้ารอเป็นนาทีแล้วได้ 413 เปล่าๆ
**แก้:** เช็ค `size` ตั้งแต่ตอนเลือกไฟล์ + ข้อความบอกให้ลบ `node_modules` ก่อนบีบอัด

### ✅ 1.5 error ถูกกลืนเงียบ 3 จุด
`.catch(() => undefined)` ทำให้หน้าโหลดค้าง/ว่างโดยไม่บอกเหตุผล:
- `settings` โหลดข้อมูลบัญชีไม่ได้ → การ์ดค้าง skeleton ตลอดกาล
- `databases` โหลดรายชื่อแอปไม่ได้ → ตัวเลือก "ผูกกับแอป" ว่างเปล่า
- `deploy?appId=` โหลดรายละเอียดไม่ได้ → ไม่รู้ว่ากำลัง redeploy แอปไหน

**แก้:** ทั้งสามจุดเด้ง toast บอกเหตุผล
(ที่จงใจให้เงียบและ **ห้ามแก้**: logout, กระดิ่งแจ้งเตือน — พังแล้วต้องไม่รบกวนงานหลัก)

## 2. การเข้าถึง (accessibility)

### ✅ 2.1 StarterFilesModal ไม่มี focus trap
ดัก Escape อย่างเดียว → Tab หลุดไปโฟกัสของหลังกล่องที่กดไม่ได้ และปิดแล้วโฟกัสหายไปที่ body
**แก้:** แยก `lib/use-modal-a11y.ts` ออกมาจาก `ConfirmDialog` แล้วใช้ร่วมกันทั้งสองกล่อง
(กล่อง modal ใหม่ทุกกล่องต่อจากนี้ให้เรียก hook นี้)

### ✅ 2.2 ช่องกรอกหน้า auth ไม่มี label ผูกกับ input
label เป็น `<div>` ลอยๆ → screen reader อ่านไม่รู้ว่าคู่กัน และคลิกข้อความไม่โฟกัสช่อง
**แก้:** `<label htmlFor>` + `id` + `aria-invalid`/`aria-describedby` ตอนมี error

### ⬜ 2.3 input อีก ~20 จุดยังไม่ผูก label
ส่วนใหญ่อยู่ใน `/deploy` (`InputRow`, `SelectRow`, ช่อง env var) และฟอร์มแก้ไขบนแดชบอร์ด
ทำแบบเดียวกับ 2.2 — แก้ที่คอมโพเนนต์กลางไม่กี่ตัวก็ครอบคลุมเกือบหมด

### ⬜ 2.4 ยังไม่เคยตรวจด้วยคีย์บอร์ดล้วน/screen reader จริง
รายการข้างบนมาจากการอ่านโค้ด ควรลองไล่ทั้งแอปด้วย Tab อย่างเดียวสักรอบ

## 3. ใช้งานได้แต่ไม่ดี

### ✅ 3.1 หน้าบันทึกการใช้งาน (`/audit`) ไม่มีตัวกรอง/ค้นหา/แบ่งหน้า
เดิม `GET /audit` คืน**ทุกแถวที่เคยเกิดขึ้น**แล้ว frontend render หมด — log โตขึ้นเรื่อยๆ
หน้าจะอืดและหาอะไรไม่เจอ
**แก้:** ย้ายการกรองไปฝั่ง backend (`queryByAccount` — decision/ค้นหา/offset/limit,
เรียงใหม่สุดก่อน, cap 500) + หน้าเว็บมีช่องค้นหา (หน่วง 300ms), ชิปกรองตามผลตัดสิน,
ปุ่ม "โหลดเพิ่ม" ทีละ 100 แถว และตัวนับ "แสดง X จาก Y"
*หมายเหตุ: audit.log ยังเป็นไฟล์แบน append-only ต้องอ่านทั้งไฟล์อยู่ดี — ถ้าวันหนึ่งอ่านช้า
ค่อยย้ายไป Postgres แล้ว query จริง ตอนนี้อย่างน้อย response ไม่โตตามอายุระบบแล้ว*

### ⬜ 3.2 ไม่มีปุ่ม "ลองใหม่" ตอนโหลดพัง
หลายหน้าโชว์ข้อความ error แล้วจบ ต้องรีเฟรชทั้งหน้าเอง

### ⬜ 3.3 หน้าว่าง (empty state) ยังเป็นข้อความเปล่าๆ
เช่น ยังไม่มีโปรเจกต์/ฐานข้อมูล — ควรมีปุ่มพาไปทำขั้นถัดไปเลย

## 4. เช็คแล้วไม่มีปัญหา (ไม่ต้องทำ)

- `alert()` / `confirm()` ของเบราว์เซอร์ถูกแทนด้วย Toast/ConfirmDialog หมดแล้ว
- `setInterval` ทุกจุดมี cleanup ครบ ไม่มี timer รั่ว
- แถบล่างมือถือไม่บังเนื้อหา (layout กัน `pb-[60px] sm:pb-0` ไว้แล้ว)
- ตาราง `/audit` มีเวอร์ชันการ์ดสำหรับมือถือแยกอยู่แล้ว ไม่ล้นจอ
- ปุ่ม submit ทุกหน้ามี `disabled` ตอนกำลังส่ง
