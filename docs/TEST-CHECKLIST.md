      ต้องเด้ง toast แดง ไม่ใช่แบนเนอร์ที่มีปุ่มลองใหม่ (ปุ่มนั้นสงวนไว้ให้ error ของการโหลด)
- [ ] **หน้าว่างต้องมีปุ่มพาไปขั้นถัดไป**
      - `/databases` ที่ยังไม่มี DB → กดปุ่มแล้วโฟกัสต้องวิ่งไปช่อง "ชื่อฐานข้อมูล" ด้านบน
      - แท็บ Domains ที่ยังไม่มีโดเมน → กดแล้วโฟกัสไปช่องกรอกโดเมน
      - แท็บ Variables ที่ยังไม่มีตัวแปร → ปุ่มแรกโฟกัสช่อง KEY, ปุ่มที่สองเปิดกล่องนำเข้า .env
      - `/audit` ตอนกรองจนไม่เหลือ → ปุ่มล้างตัวกรอง · ตอนไม่มี log เลย → ปุ่มไปหน้าดีพลอย
- [ ] **ช่องกรอกทุกช่องคลิกที่ข้อความ label แล้วต้องโฟกัสเข้าช่อง**
      (เทสง่ายๆ ที่ /deploy: คลิกคำว่า "Branch" / "Runtime" / "ชื่อโปรเจกต์" / "Port")
      และที่ /account คลิก "รหัสผ่านปัจจุบัน" / "รหัสผ่านใหม่"
- [ ] **กด Enter ในช่อง token (ตั้งค่า → บัญชีที่เชื่อมต่อ) ต้องส่งฟอร์ม** (ของใหม่)
- [ ] **กด Enter ในช่องรหัส 2FA หน้าตั้งค่า ต้องยืนยัน** + บนมือถือต้องขึ้นแป้นตัวเลข (ของใหม่)
- [ ] **`/audit` ค้นหาด้วย score / findings** — หาแถวที่คอลัมน์รายละเอียดมี `score=N`
      แล้วพิมพ์ทั้ง `N` และ `score=N` ต้องเจอทั้งสองแบบ · พิมพ์ `findings` ต้องเจอแถวที่มี finding
      *(เดิมพิมพ์เลข score ที่เห็นอยู่บนจอแล้วหาไม่เจอ)*
- [ ] **`/audit` ตัวกรองช่วงวันที่** (ของใหม่)
      - เลือกวันเดียว (from = to) → ต้องได้เฉพาะแถวของวันนั้น
      - เลือกแค่ from → ได้ตั้งแต่วันนั้นถึงปัจจุบัน · เลือกแค่ to → ได้ตั้งแต่ต้นถึงวันนั้น
      - **จุดที่ต้องดูให้ดี:** แถวที่เวลาไทยอยู่ช่วง 00:00–07:00 (เช่น `18/7 01:24`)
        ต้องโผล่เมื่อเลือกวันที่ **18** ไม่ใช่วันที่ 17 — ถ้าเลื่อนไปวันก่อนหน้าคือ timezone พัง
      - เลือก from แล้วช่อง to ต้องเลือกวันก่อนหน้านั้นไม่ได้ (และกลับกัน)
      - ใช้ร่วมกับชิป BLOCK/ALLOW + คำค้น พร้อมกันต้องกรองซ้อนกันถูก
      - กด × ข้างช่องวันที่ → ล้างแค่ช่วงวันที่ ชิป/คำค้นยังอยู่
      - กด "โหลดเพิ่ม" ตอนกรองวันที่อยู่ → แถวที่ต่อมาต้องอยู่ในช่วงเดิม ไม่หลุดช่วง
- [ ] **`/audit` ทนบรรทัดเสีย** — เทสด้วยตาไม่ได้ตรงๆ ต้องให้คนที่เข้า server ได้ทำ:
      ต่อบรรทัดขยะท้าย `data/audit.log` (`echo '{"ts":"x' >> data/audit.log`) แล้วรีเฟรช `/audit`
      **ต้องยังเห็น log ครบเหมือนเดิม** (เดิมจะกลายเป็น "ยังไม่มีเหตุการณ์" ทั้งหน้า)
      และใน journal ของ backend ต้องมี warn ว่ามีกี่บรรทัดที่อ่านไม่ได้ — เทสเสร็จลบบรรทัดขยะออก
